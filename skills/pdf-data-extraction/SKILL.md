# PDF信息提取汇总技能

把一叠PDF按"找关键词页面 → 转Word → 清洗 → 汇总Excel"四步流水线处理，最终输出一张Excel汇总表。找不到《基本情况表》或表格提取失败时，流水线会自动**兜底提取**（步骤5，见下）。

## 流水线

```
PDF文件夹（支持根目录平铺 或 按子文件夹分组）
  │ 步骤1 extract_pdf_pages.py   扫描PDF文字，抽取含关键词的页面 → *_基本情况表.pdf
  ▼
步骤2 pdf_to_word.py          提取页PDF批量转 .docx
  ▼
步骤3 clean_word.py           Word原地清洗：表格拉宽 + 去除所有空格（修复被拆散的数字）
  ▼
步骤4 extract_to_excel.py     从表格中提取字段 → 投标人信息汇总.xlsx
  ▼
步骤5 fallback_fill.py(流水线自动)  失败投标人兜底：表格重建 / 文本解析，重跑步骤4
```

## 前置条件

- Python 3.8+；使用前先 `python --version` 确认。
- 依赖：`pdfplumber PyPDF2 pdf2docx python-docx pandas openpyxl`
  - 一键安装：运行本技能目录下的 `install.ps1`
  - 或手动：`python -m pip install pdfplumber PyPDF2 pdf2docx python-docx pandas openpyxl`
- 若运行时报缺模块，先安装依赖再继续，不要硬跑。

## 执行约定（重要）

1. **始终用 `python -X utf8` 运行脚本**，防止中文输出乱码。
2. 所有路径用双引号包住（中文/空格路径）。
3. 每步结束后检查脚本打印的统计与"失败/未找到"清单，如实报告给用户；不要忽略失败文件。
4. 输入输出路径以用户给出的为准；用户未给出时先询问，不要自行猜测路径。

## 分步执行

### 步骤1：提取关键词页面

```powershell
python -X utf8 "<技能目录>\scripts\extract_pdf_pages.py" --input "<PDF文件夹>" --output "<输出文件夹>"
```

| 参数 | 说明 |
|------|------|
| --input | 包含PDF的文件夹 |
| --output | 提取页面的输出文件夹（不存在会自动创建） |
| --keywords | 逗号分隔关键词，默认：投标人基本情况表,投标基本情况表,基本情况表,投标人基本情况,注册地址 |
| --suffix | 输出文件名后缀，默认 `_基本情况表` |
| --workers | 并行进程数，默认 6（扫描为多进程并行，大文件建议 4-6） |

两种扫描模式（自动）：
- 根目录有PDF → 逐个提取，不限制数量；
- 根目录无PDF → 按子文件夹分组，每组找到第一个含关键词的PDF即停。

关键词页匹配规则：优先选取**同时含关键词和文件名公司名**的页面（避免联合体投标时误取联合体成员的表），找不到时退回第一个含关键词的页面。

### 步骤2：PDF转Word

```powershell
python -X utf8 "<技能目录>\scripts\pdf_to_word.py" --input "<步骤1输出文件夹>" --output "<Word输出文件夹>"
```

### 步骤3：清洗Word（原地修改）

```powershell
python -X utf8 "<技能目录>\scripts\clean_word.py" --input "<Word文件夹>" --mode all
```

| 参数 | 说明 |
|------|------|
| --mode all | 去除所有空格（默认，推荐）——把"17730225 964"修成"17730225964" |
| --mode single | 只合并多余空格，保留单词间单个空格（文档含英文时用） |
| --col-width | 表格列宽（英寸），默认 4.0 |

⚠️ 原地修改，如需原件请先备份。

### 步骤4：汇总Excel

```powershell
python -X utf8 "<技能目录>\scripts\extract_to_excel.py" --input "<Word文件夹>" --output "<汇总.xlsx>"
```

--output 省略时输出到输入文件夹下的 `投标人信息汇总.xlsx`。

## 一键流水线（推荐）

四步+兜底一次跑完：

```powershell
python -X utf8 "<技能目录>\scripts\run_pipeline.py" --pdf-folder "<PDF文件夹>" --output "<汇总.xlsx>"
```

| 参数 | 说明 |
|------|------|
| --pdf-folder | 原始PDF文件夹（必填） |
| --output | 最终Excel路径，默认 `<pdf-folder>\投标人信息汇总.xlsx` |
| --work-dir | 中间文件目录，默认输出Excel同目录下 `流水线中间文件\` |
| --keywords / --suffix | 同步骤1 |
| --skip-clean | 跳过清洗步骤 |

中间产物保留在 `流水线中间文件\01_提取页面` 和 `02_转Word`，便于人工抽查。

## 步骤5：兜底提取（流水线自动执行，也可单独运行）

当投标文件中**没有《投标人基本情况表》**（如政府采购竞争性谈判/公开招标响应文件），或pdf2docx转换丢表格导致步骤4提取失败时，从PDF其他位置提取信息：

| 目标字段 | 数据来源 | 说明 |
|---------|---------|------|
| 投标人名称 | 《唱标信息》"投标人名称：X"/"供应商名称：X"；或法代证明书"单位名称/投标人：X" | 排除模板值（none/单位性质/盖章等） |
| 注册地址 | 法代证明书"地 址：X" | 截到成立时间/经营期限 |
| 法定代表人+电话 | 法代证明书"姓名：X" + "手机号码/联系电话：X" | 只取**已填写**的页（含真实电话数字），忽略空白模板页 |
| 联系人+电话 | 《授权书》"授权代表联系方式：X" | 联系人栏填**授权代表**，与基本情况表口径不同，报告时需说明 |

两级策略：
1. **表格重建**：源PDF中"投标人名称/供应商名称 + 注册地址"的表格页，用pdfplumber find_tables按表格线重建Word表格（修复pdf2docx因文字重叠/拆表丢内容的问题）；
2. **文本解析**：无表格时按上表正则解析（解析前去除全部空格，兼容"手 机 号 码"等拆字写法）。

单独运行：
```powershell
python -X utf8 "<技能目录>\scripts\fallback_fill.py" --pdf-folder "<源PDF文件夹>" --word-dir "<02_转Word>" --failed "投标人A" "投标人B"
```
生成与步骤2同构的docx后，重跑步骤4即可并入汇总。

## 默认提取字段（步骤4）

| 字段 | 提取方式 |
|------|---------|
| 投标人名称 | 表格中"投标人名称"单元格后一格的文本 |
| 注册地址 | "注册地址/详细地址/注册地"后文本（自动截掉"邮政编码"部分） |
| 联系人 / 联系人电话 / 电子邮件 | "联系方式/联系人"行；电话支持11位手机号与"区号-号码"座机号 |
| 法定代表人 / 法定代表人电话 | "法定代表人"行中"姓名"单元格 |
| 技术负责人 / 技术负责人电话 | "技术负责人"行中"姓名"单元格 |

字段与提取规则位于 `scripts/extract_to_excel.py` 的 COLUMN_ORDER 与 extract_bidder_info_from_word()，换业务场景时改这里。

## 注意事项

- **扫描件PDF**（无文字层）提取不到任何文字 → 兜底也取不到，报告用户先OCR（Adobe/WPS等），勿静默继续。
- 兜底提取仍有取不到的情况：投标文件为空白模板/壳文件（仅封面）→ 只能提取名称；源PDF损坏（如0KB/15字节空文件）→ 报告用户从系统重新下载。
- 步骤4只支持 .docx；遇 .doc 会跳过并提示，需用户用Word/WPS另存为 .docx。
- 自动跳过 `~$` 开头的Word临时文件。
- pdf2docx 转换的表格版式偶有偏差；流水线兜底已含表格重建，仍失败可让用户手工调整Word后重跑步骤3、4。
- 汇总Excel被Excel占用时会写入失败，提示用户关闭后重跑。
