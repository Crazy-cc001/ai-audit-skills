# 银行流水 × 记账凭证 核对

## 用途

把银行侧的原始材料变成可核对的结构化流水，与账上凭证勾稽，并**在数字对不上时先拦住流程**——
不要让人拿一个不可靠的数字去推导业务结论。

---

## 🔴 五条铁律（动手前必读）

### 铁律 1：一律以「对账单」为准，绝不用「回单」逐笔拼凑

| 材料 | 特点 |
|---|---|
| **对账单** | ✅ 自带三个自校验锚点：**承前页余额 · 逐笔余额 · 月末余额**。优先用它 |
| 回单 / 交易通知 | ❌ 逐笔、多为扫描件、必须看图或 OCR，**极易读错数字**。只作附件 |

> **真实事故**：9 页回单扫描件，看图读错 4 处 ——
> 收款 760,000（实 500,000）· 付款方向读反 · 付 292,336.40 看成 382,336.40 ·
> 整笔 300,000.00 漏记。并据此**臆造出一个根本不存在的「超付 496.40」**，还编了 4 种解释。
> 换成对账单后 18 笔全部对上，差异归零。

**同一目录常同时存在扫描件与电子版。先找电子版！**

### 铁律 2：回单上的「大写金额」必须核

回单必有「大写金额」栏（例：`人民币贰拾玖万贰仟叁佰叁拾陆元肆角整`）。
**阿拉伯数字与大写双向校验**；不一致或看不清 → **该笔不采用**，回原件重看。

### 铁律 3：数字对不上时，先怀疑自己的输入

| | 顺序 |
|---|---|
| ❌ 错误 | 金额对不上 → 猜业务原因（编故事、造「超付」「重复开票」） |
| ✅ 正确 | 金额对不上 → **回原件复核** → 仍不符 → 才谈业务解释 |

**先把输入钉死，再谈业务。**

### 铁律 4：同一对方同月多笔，必须逐笔列全

禁止只看到一笔就下结论。事故中就是漏了 0824 那笔 300,000.00。

### 铁律 5：勾稽不平 → 禁止输出凭证

**凭证的银行存款发生额必须与对账单吻合**；不平就停手查输入，不要带着差异往下做。

## 处理流程

### 步骤 1 · 探测材料，决定路线

```bash
python scripts/probe_pdf.py "<pdf路径>"
```

- **字符数 > 200** → 有文字层 → 走 **步骤 2A**
- **字符数 = 0** → 纯扫描件 → 走 **步骤 2B**，并**同时找找同目录有没有电子版**

### 步骤 2A · 解析电子版对账单

```bash
python scripts/parse_statement.py "<pdf路径>" --json out.json
```

脚本做的事：
1. 按坐标重组表格（电子版文字是**碎片化**的，`20260826`/`114534`/`借方`/`220.83` 各自独立）
2. **序号锚点法**：`x < 35 且纯数字` 的词 = 序号；行范围取 `[锚y−25, 下一锚y−25)`
3. **三重自校验**并打印结论

列区间（光大对账单，按需微调）：
`序号 <35｜日期 35–85｜时间 85–122｜借贷 122–160｜金额 160–252｜余额 252–305｜
对方账号 305–368｜对方名称 368–420｜凭证号 420–462｜摘要 462–540｜流水号 >540`

### 步骤 2B · 扫描件直接看图

```bash
python scripts/render_page.py "<pdf路径>" --page 6 --dpi 130 --rotate -90 --half R
```

- 先试 `--rotate 90` / `--rotate 270` 找正方向（扫描件常整页旋转 90°）
- `--half L|R` 用于「一页并排两张回单」的版式
- 生成 PNG 后用**看图工具直接看**（OCR 对密集表格失效）
- **看图时必须读「大写金额」栏**

### 步骤 3 · 三重自校验（缺一不可）

1. **金额合计 = 表头发生额**（如「借方 15 笔 724,492.22」）
2. **余额链倒推自洽**：`上笔余额 ± 本笔金额 = 本笔余额`，每一笔都要过
3. **承前页 = 上月末账面余额**

> ⚠️ 反推承前页要用**最早那笔**（列表末尾），不是最新那笔。混淆过这个。

### 步骤 4 · 与凭证逐笔勾稽

生成核对表：每笔流水 ↔ 对应凭证号 ↔ 核对结果。

**同时单独列出「不经过银行账户的凭证」**，它们本来就不该出现在对账单里：
计提工资/税费 · 挂应付账款的采购 · 挂应收账款的销售 · 员工垫付的报销 · 承兑汇票出票。

### 步骤 5 · 输出

- 逐笔核对表（xlsx）
- 差异清单（若有）
- 明确写出：**银行存款 借 X / 贷 Y / 净 Z，与对账单是否吻合**

## 常见坑

| 坑 | 表现 | 对策 |
|---|---|---|
| 扫描件数字看错 | `292,336.40` → `382,336.40` | 核大写金额；优先电子版 |
| 漏记同对方另一笔 | 只记 292,336.40，漏 300,000.00 | 逐笔列全 |
| 反推承前页取错对象 | 用最新一笔而非最早一笔 | 取列表末尾那笔 |
| 行高不固定 | 对方名称占 2–3 行，锚点间距不等 | 用「锚y±25 到下一锚y−25」切分 |
| 一页并排两张回单 | 直接渲染是横向碎片 | 先按 x 裁半，再各转正 |
| 把「承兑」当普通付款 | 摘要「承兑」= 汇票到期扣款，仍走银行存款 | 按实际扣款处理 |
| 拿票号差 / 金额巧合当判据 | 「金额一样 = 重复开票」 | 判重只看票号；不下业务结论 |

## 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/probe_pdf.py` | 探测页数 / 字符数 / 内嵌图 / 页面尺寸 → 决定走电子版还是看图 |
| `scripts/parse_statement.py` | 电子版对账单按坐标结构化 + 三重自校验 |
| `scripts/render_page.py` | 扫描件渲染成 PNG（支持旋转、左右裁半），供直接看图 |

依赖：`pymupdf`（`pip install pymupdf`）。
