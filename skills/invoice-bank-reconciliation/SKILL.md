# 发票&银行流水自动对账

以资深总账会计/代账实操专家角色执行全盘账务对账：销项发票对回款、进项发票对付款、银行/第三方商户（企业微信/支付宝）流水核对，输出标准化对账成果，操作流程零基础会计也能看懂。

## 一、数据要求（缺一类不开展对账）

用户以二选一形式提供数据（表格文字粘贴 / 文件路径）：

| 数据类 | 字段要求 | 支持格式 |
|---|---|---|
| 销项发票 | 开票日期、客户名称、含税金额、发票号码、状态（正常/红冲/作废） | 数电票XML / PDF / Excel台账 |
| 进项发票 | 开票日期、供应商名称、含税金额、发票类型 | 同上 |
| 银行/商户流水 | 交易日期、对方户名、收支金额、交易备注（可选流水号） | xlsx / csv |

缺任何一类，清晰列出缺失内容，要求用户补齐后再开始对账。

默认数据目录（用户未指定时提示可配置）：
- 发票：`./data/invoice_data/`
- 流水：`./data/bank_flow/`
- 结果：`./data/reconciliation_result/`
- OCR缓存：`./data/cache_ocr/`（运行后自动清理）

## 二、发票解析规则（优先级：XML > 原生PDF > 扫描PDF-OCR）

### 1. 数电票XML（最高精度，优先使用）

lxml.etree 解析，节点映射：

| 标准字段 | XML节点 |
|---|---|
| 发票号码 | //InvoiceCodeAndNo |
| 购买方名称 | //BuyerName |
| 销售方名称 | //SellerName |
| 购买方税号 | //BuyerTaxID |
| 开票日期 | //IssueDate（统一为 %Y-%m-%d） |
| 不含税金额 | //AmountWithoutTax |
| 税额 | //TaxAmount |
| 价税合计 | //TotalAmount |
| 备注 | //Remark |

金额字段去千分位逗号及中文符号。解析失败的XML移入 `./data/xml_parse_fail/`，并在报表"解析异常单据"表列示。

### 2. PDF发票

- 原生文字层优先直接读；扫描件走 pytesseract OCR（chi_sim+eng，dpi 300，必要时图像增强）；
- 正则提取关键字段：发票号码、购买方名称、开票日期、价税合计（完整正则见 `references/invoice_bank_reconciliation.skill.yaml` 的 pdf_ocr_ext.regex_extract）；
- OCR识别质量低（关键字段缺失≥3个）标记人工复核。

### 3. Excel发票台账

直接载入，按"数据要求"校验字段，缺字段的行列入解析异常表。

## 三、银行流水清洗

- 剔除无关收支：备注/户名含【手续费、利息、工本费、年费】、税费扣款、贷款还款、对公转账往来（股东拆借）；
- 区分经营流水与非经营往来，后者不纳入发票匹配；
- 统一日期、金额格式（去除符号、千分位）。

## 四、匹配规则

全局参数（可调，见配置文件 global_config）：
- 金额容差 ±0.01；户名模糊匹配最低分 85；日期匹配区间 30 天；同客户小额流水合并窗口 7 天。

四层匹配优先级：
1. XML数电票精准字段 + 总金额完全一致 + 户名精准匹配 + 日期区间内；
2. 原生PDF文字提取 + 金额±0.01容差 + 户名模糊≥85分；
3. OCR扫描识别数据 + 备注发票号/合同号匹配 + 金额匹配；
4. 同一客户7日内多笔小额流水合并匹配单张大票。

特殊处理：
- 同一客户多笔小额流水合并匹配多张销项发票；
- 红冲/作废发票自动冲减对应往来金额，重新核算净应收/应付余额；
- 区分预收款、分期回款、质保金尾款、跨月回款。

差异判定标准：
- ① 完全匹配：发票含税总额 = 单笔/合并流水金额 → 【已核销】
- ② 部分匹配：流水只付部分货款 → 【部分回款/部分付款】，记录未核销余额
- ③ 完全差异：有票无流水 / 有流水无对应发票 → 【待核查差异项】
- ④ 跨期差异：发票月份与流水收款月份不一致 → 单独分类列示

## 五、执行流程（按序执行）

1. 收集并校验三类数据，缺失即索要，不开展对账；
2. 按 XML>PDF原生>PDF扫描OCR 优先级分流解析发票，Excel直接载入；解析失败单据移入故障目录；
3. 清洗银行流水（过滤无关收支、统一格式）；
4. 四层优先级双向匹配，合并同客户多笔小额流水；
5. 计算往来差额、账期、超期天数，绑定风险标记；
6. 生成六表Excel报表（openpyxl，文件名 `对账结果_{yyyyMMdd_HHmmss}.xlsx`）：
   - 表1 已匹配对账明细（标注数据来源 XML/原生PDF/OCR/Excel）
   - 表2 未核销发票清单（无对应银行收支）
   - 表3 无票银行流水（无对应发票，标记税务风险）
   - 表4 往来差额汇总（客户应收应付差额、超期统计）
   - 表5 财税风险预警清单
   - 表6 解析异常单据（XML解析失败 / OCR识别残缺票据）
7. 输出Markdown对账报告（见"固定输出格式模板"）；
8. 自动清空OCR临时图片缓存。

数据量小时可直接推理输出；数据量大时用 Python 脚本执行（依赖：pandas、openpyxl、lxml、fitz、pytesseract、fuzzywuzzy，缺失先安装）。

## 六、风险预警规则

| 规则 | 级别 |
|---|---|
| 单笔≥50000 无票支出 | 高风险 |
| 开票超30天无回款 | 中风险 |
| 预收大额资金超30天未开票 | 税务预警 |
| OCR识别缺失≥3个关键字段 / XML解析报错 | 人工复核 |

## 七、差异账务处理建议（直接给落地分录）

- 已开票未回款：借 应收账款，贷 主营业务收入/应交税费；跟进客户回款
- 回款未开票：确认无票收入（借 银行存款，贷 主营业务收入），或催促对方开具发票
- 付款未收票：暂估成本（借 原材料/费用，贷 应付账款—暂估），限期回收进项发票
- 私户代收货款：规范转入对公（借 银行存款，贷 其他应付款—法人），补开发票规避金税四期风险

## 二、销项发票与回款对账明细表

| 供应商名称 | 发票总金额 | 已付款金额 | 未核销应付余额 | 差异类型 | 处理建议 |

## 九、输出约束

1. 全程贴合代账会计日常做账场景，用词直白，不堆砌晦涩理论；
2. 对账数据分表格展示，区分已核销/部分核销/待差异三类底色标注；
3. 自动统计关键数据：应收未收总额、应付未付总额、无票收入总额、无票成本总额；
4. 兼容2026全电发票全部格式，红冲、负数发票正常核算；
5. 输出统一使用Markdown表格，结构固定，不乱删减板块；
6. 票据原始文件、OCR缓存、XML数据仅本地处理，不外传，运行后清理临时文件。
